# پنل مدیریت نسخه‌ی ۲ — نصب، تست و برگشت

این بسته **هیچ فایل زنده‌ای را عوض نمی‌کند**. پنل جدید با نام `admin2.html` کنار پنل فعلی (`admin.html`) نصب می‌شود؛ هر دو هم‌زمان کار می‌کنند و با همان حساب ورود. وقتی مطمئن شدی، جایگزینش می‌کنی (۱ دقیقه) و هر وقت خواستی برمی‌گردی.

## محتوای بسته

| فایل | کار |
|---|---|
| `public_html/admin2.html` | پوسته‌ی پنل جدید |
| `public_html/assets/admin/*.css, *.js` | کد پنل (یک CSS + ۱۰ فایل JS) |
| `public_html/assets/supabase.min.js` | کتابخانه‌ی Supabase (اگر قبلاً از بسته‌ی «سریع‌تر» نصب کرده‌ای، همان است) |
| `public_html/admin-chunk-upload.php` | آپلود تکه‌ای ویدیوهای حجیم (جدید) |
| `public_html/admin-files.php` | فهرست/حذف فایل‌های هاست و وضعیت سرور (جدید) |
| `sql/admin-upgrade.sql` | جدول‌های جدید و اجازه‌ی خواندن تراکنش‌ها (در Supabase اجرا می‌شود) |

## نصب (۱۵ دقیقه)

### ۱) آپلود فایل‌ها
زیپ را در `public_html` آپلود و **Extract** کن. همه‌ی فایل‌ها جدیدند، چیزی بازنویسی نمی‌شود
(فقط اگر `assets/supabase.min.js` از قبل بود، یکی هستند).

### ۲) اجرای SQL (۱ دقیقه)
Supabase ← **SQL Editor** ← محتوای `admin-upgrade.sql` را بچسبان ← **Run**.
- چیزی حذف یا عوض نمی‌شود؛ چند بار اجرا کردنش هم مشکلی ندارد.
- بدون این مرحله پنل کار می‌کند، ولی «تراکنش‌ها / آمار فروش / دستگاه‌ها / یادداشت / گزارش فعالیت» خالی یا ناقص‌اند
  (برای خواندن جدول `payments` و `user_sessions` باید اجازه‌ی ادمین داده شود).

### ۳) تست (بدون ریسک)
`https://mehdimehrabi.ir/admin2.html` را باز کن و با همان ایمیل/رمز همیشگی وارد شو. لیست تست:

| # | کار | باید ببینی |
|---|---|---|
| ۱ | داشبورد | فروش امروز/۷ روز/ماه با اعداد درست (با پنل تراکنش‌ها مقایسه کن) |
| ۲ | تراکنش‌ها | ۳۴+ تراکنش، فیلترها، جستجوی کد رهگیری |
| ۳ | وضعیت سیستم | همه‌ی موارد «سالم»؛ جدول‌ها «هست»؛ PHP/دیسک نمایش داده شود |
| ۴ | هنرجویان ← یک نفر | پروفایل، دوره‌ها، پرداخت‌ها، دستگاه‌ها |
| ۵ | دوره‌ها ← یک دوره ← ذخیره (بدون تغییر) | «روی سایت اعمال شد ✓» |
| ۶ | دوره ← جلسات | لیست جلسات؛ ▲▼ و کشیدن کار کند (روی دوره‌ی تستی/غیرفعال امتحان کن) |
| ۷ | یک دوره‌ی تستی بساز ← جلسه با فایل کوچک ← بعد حذفش | آپلود تا ۱۰۰٪ برود |
| ۸ | آپلود فایل بزرگ (مثلاً ۳۰۰ مگ) روی دوره‌ی تستی | تکه‌تکه با درصد و سرعت آپلود شود |
| ۹ | کتابخانه‌ی فایل | فایل‌های ویدیو با «استفاده‌شده در …» |
| ۱۰ | بلاگ ← یک پست باز کن | ویرایشگر؛ (ذخیره نکن اگر نمی‌خواهی) |

### ۴) جایگزینی پنل قدیمی (وقتی تست‌ها خوب بود)
در File Manager:
1. `admin.html` را به `admin-old.html` تغییر نام بده (پنل قدیمی برای برگشت می‌ماند).
2. `admin2.html` را به `admin.html` تغییر نام بده.

> بعد از جایگزینی مرورگر را Ctrl+F5 کن. اگر Cloudflare صفحه را کش کرده بود، یک‌بار Purge Everything بزن.

### برگشت (۱ دقیقه)
`admin.html` را `admin2.html` کن و `admin-old.html` را دوباره `admin.html`.
چون پنل جدید در دیتابیس فقط **جدول‌های جدید** می‌سازد و داده‌ای را تغییر ساختاری نمی‌دهد، برگشتن هیچ مشکلی ایجاد نمی‌کند.

## چه چیزهایی تست شده و چه چیزهایی نه (صادقانه)

**تست‌شده در محیط آزمایشی** (مرورگر واقعی Chromium + Supabase ساختگی + PHP واقعی + ساختار داده‌ی خودِ `payments_rows.sql` شما):
همه‌ی صفحه‌ها بدون خطا باز می‌شوند؛ اعطای دسترسی دستی (کاربر جدید/موجود/تکراری)؛ تراکنش‌ها و فیلتر/جستجو/Excel؛
رفع «پرداخت موفق بدون دسترسی»؛ هنرجویان (جستجو، ویرایش، شماره‌ی تکراری، دستگاه‌ها، یادداشت، ادغام)؛
دوره (ساخت، قیمت/تخفیف، محافظ تغییرات ذخیره‌نشده، حذف مسدود برای دوره‌ی دارای هنرجو)؛
جلسات (▲▼، کشیدن و رها کردن، افزودن، حذف، پیوست)؛ آپلود ساده و تکه‌ای (۲۰ و ۲۸ مگابایت، با قطع‌شدن‌های ساختگی وسط آپلود و محتوای یکسان md5)؛
رد پسوند غیرمجاز و درخواست بدون توکن؛ کتابخانه‌ی فایل؛ بلاگ؛ صندوق پیام؛ ذخیره‌ی متن‌ها؛ جستجوی Ctrl+K؛
رفتار هنگام قطع دیتابیس؛ و اینکه متن‌های مخرب (`<script>` در نام/دیدگاه/عنوان) هرگز اجرا نمی‌شوند و ستون `password_hash` هرگز خوانده نمی‌شود.

**روی سرور و Supabase واقعی تست نشده** (باید در مرحله‌ی ۳ خودت ببینی):
- اجازه‌های RLS واقعی (جدول `payments` و `user_sessions` برای ادمین) — با اجرای SQL درست می‌شود؛ اگر تراکنش‌ها خالی بود یعنی SQL اجرا نشده.
- دکمه‌ی «بررسی از زیبال» که `verify.php` واقعی را صدا می‌زند (بی‌خطر و تکرارپذیر است، ولی با زیبال واقعی امتحان نشده).
- آپلود تکه‌ای روی ساب‌دامین `upload.mehdimehrabi.ir` و LiteSpeed واقعی (اگر ساب‌دامین به همان `public_html` اشاره نکند، خودکار از خود سایت امتحان می‌کند).
- ورود دومرحله‌ای (2FA) با Supabase Auth واقعی (در تنظیمات و امنیت؛ اختیاری است، اول با یک مرورگر دیگر امتحان کن تا قفل نشوی).
- نمایش در Safari/گوشی واقعی.

## نکته‌های امنیتی (فقط اطلاع؛ طبق گفته‌ی خودت اقدامی نشده)
- فایل‌های PHP ادمین (آپلودها و `admin-files.php`) فقط «معتبر بودن توکن Supabase» را چک می‌کنند، مثل فایل‌های قبلی. تا وقتی ثبت‌نام عمومی Supabase Auth خاموش است همین کافی است.
- «نقش‌ها» (پشتیبان/ویرایشگر) فقط **رابط پنل** را محدود می‌کند، نه دیتابیس. به همکار فقط وقتی حساب بده که کاملاً به او اعتماد داری.
- SQL این بسته به کاربر وارد‌شده اجازه‌ی کامل روی `payments` و `user_sessions` می‌دهد (مثل بقیه‌ی جدول‌های پروژه). ستون `token` نشست‌ها هیچ‌وقت در پنل خوانده یا نمایش داده نمی‌شود.
