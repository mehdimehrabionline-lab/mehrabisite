# کد تخفیف و کد معرف — نصب، تست و برگشت

دو نوع کد، هر خرید فقط **یک** کد:
- **کد تخفیف**: درصد یا مبلغ ثابت از پرداخت خریدار. (اختیاری: فقط یک دوره، سقف تعداد، تاریخ انقضا)
- **کد معرف**: همان تخفیف برای خریدار + **پورسانت جدا برای هر معرف** (درصد یا مبلغ ثابت) که از **مبلغ بعد از تخفیف** حساب می‌شود. با هر خرید موفق، پیامک به **شماره‌ی خودِ معرف** می‌رود و در پنل گزارش پورسانت داری (+ دکمه‌ی پیامک گزارش).

## ⚠ این بسته فایل‌های زنده‌ی فروش را عوض می‌کند — ترتیب و بکاپ مهم است

| فایل (در `public_html`) | وضعیت |
|---|---|
| `pay.php` | **جایگزین** (فقط ۱۴ خط اضافه؛ بدون کد دقیقاً مثل قبل کار می‌کند) |
| `verify.php` | **جایگزین** (۷ خط اضافه؛ خطای کدها هرگز تأیید پرداخت را خراب نمی‌کند) |
| `course.html` | **جایگزین** (کادر «کد تخفیف دارم» + لینک معرف). ⚠ این نسخه شامل اصلاح شماره‌ی موبایل (بسته‌ی `03-phone-fix`) هم هست؛ اگر آن را قبلاً نصب کرده‌ای همان است |
| `api/promo.php` | جدید |
| `promo-check.php` | جدید |
| `send-referral-report.php` | جدید |

### ۰) بکاپ (۲ دقیقه) — بیرون از `public_html`
در home پوشه‌ی `backup-promo` بساز و `pay.php  verify.php  course.html` را در آن Copy کن.

### ۱) پنل جدید (`admin2.html`) باید نصب باشد
بسته‌ی پنل که قبلاً فرستادم **به‌روز شد** (صفحه‌ی «کدهای تخفیف و معرف» اضافه شد): زیپ جدید پنل را دوباره Extract کن (روی همان فایل‌ها می‌نشیند).

### ۲) SQL (۱ دقیقه)
Supabase ← SQL Editor ← `promo-upgrade.sql` ← Run. دو جدول جدید + سه ستون **اختیاری** به `payments` (`promo_code`, `original_amount`, `discount_amount`). چیزی حذف نمی‌شود. کدها و شماره‌ی معرف‌ها برای عموم خوانا نیست.

### ۳) فایل‌های جدید (بی‌خطر) — `1-new-files.zip`
`api/promo.php`، `promo-check.php`، `send-referral-report.php` را آپلود کن. تا وقتی `pay.php/verify.php` را عوض نکرده‌ای هیچ اثری ندارند.

### ۴) ساخت یک کد آزمایشی
پنل ← **کدهای تخفیف و معرف** ← «کد تخفیف» ← مثلاً `TEST1` با ۱۰٪ تخفیف و **سقف تعداد ۱** (بعد از آزمایش غیرفعالش کن). برای معرف: «کد معرف» ← نام و موبایل معرف (یک شماره‌ی خودت) + درصد پورسانت.

### ۵) جایگزینی `pay.php` و `verify.php` و `course.html` — `2-swap-live.zip`
جایگزین کن؛ بعد با خودت (یک دوره‌ی ارزان یا حساب تستی):
1. صفحه‌ی دوره ← «🎟 کد تخفیف دارم» ← کد را بزن ← «اعمال» ← مبلغ جدید دیده می‌شود.
2. خرید بدون کد را هم امتحان کن (باید مثل قبل باشد).
3. خرید با کد را کامل کن؛ در پنل: تراکنش‌ها ← جزئیات ← «کد تخفیف/معرف»؛ و «کدها ← مصرف» یکی زیاد شود.

### برگشت (۱ دقیقه)
سه فایل `backup-promo` را روی `public_html` کپی کن. فایل‌های جدید و جدول‌ها می‌توانند بمانند و بی‌اثرند.

## پیامک معرف (یک‌بار تنظیم)
پیامک با «الگو» (Template) تأییدشده‌ی SMS.ir می‌رود، مثل پیامک خرید موفق. در پنل SMS.ir دو الگو بساز، شناسه‌ها را در پنل ← کدها ← **تنظیمات پیامک** بنویس:

1. **خرید جدید با کد معرف** (خودکار با هر فروش) — متغیرها `NAME`, `AMOUNT` (نام دوره عمداً در پیامک نیست):
   `سلام #NAME# عزیز، خرید جدیدی با کد معرف شما ثبت شد. پورسانت شما: #AMOUNT# تومان`
2. **گزارش** (دستی با دکمه‌ی «پیامک گزارش») — متغیرها `NAME`, `COUNT`, `PENDING`, `PAID`:
   `سلام #NAME# عزیز، گزارش شما: #COUNT# فروش — پورسانت پرداخت‌نشده: #PENDING# تومان — پرداخت‌شده: #PAID# تومان`

تا شناسه ثبت نشود پیامکی نمی‌رود ولی پورسانت ثبت می‌شود. هر پارامتر حداکثر ۲۵ کاراکتر است (محدودیت SMS.ir).

## قواعد (همه در سرور اعمال می‌شود، نه مرورگر)
- مبلغ نهایی هیچ‌وقت زیر ۱٬۰۰۰ تومان نمی‌شود.
- معرف نمی‌تواند با کد خودش (همان موبایل) بخرد.
- کد غیرفعال، منقضی، پر‌شده یا مخصوص دوره‌ی دیگر رد می‌شود.
- مصرف کد و پورسانت **فقط بعد از تأیید پرداخت** ثبت می‌شود و فقط یک‌بار (verify تکراری یا «بررسی از زیبال» دوباره چیزی ثبت نمی‌کند).
- سقف ۲۰ بررسی کد در ۱۰ دقیقه برای هر نشست (جلوی حدس‌زدن کدها).
- شمارش مصرف بعد از پرداخت موفق افزایش می‌یابد؛ اگر چند نفر هم‌زمان با آخرین ظرفیت یک کد پرداخت را شروع کنند، ممکن است یکی-دو مصرف بیش از سقف ثبت شود (پرداخت‌شده رد نمی‌شود).

## لینک اشتراک معرف
پنل ← کدها ← دکمه‌ی 🔗 کنار هر کد: `https://mehdimehrabi.ir/c/<دوره>?ref=CODE`. هر کس با این لینک بیاید، کد خودکار در کادر پر می‌شود و حتی اگر بعداً وارد شود یا ثبت‌نام کند در همان مرورگر حفظ می‌ماند.

## تست‌شده / تست‌نشده
**تست‌شده** (PHP واقعی + Supabase/زیبال/SMS ساختگی + مرورگر): محاسبه‌ی درصد/مبلغ/حداقل ۱۰۰۰؛ همه‌ی ردها (منقضی، پر، غیرفعال، دوره‌ی دیگر، خود‌معرف، ناموجود، مخرب)؛ ساخت پرداخت با مبلغ درست و ارسال همان مبلغ به زیبال؛ پورسانت ۱۰٪ از مبلغ بعد از تخفیف و مبلغ ثابت؛ پیامک به معرف با پارامترهای درست؛ verify تکراری؛ پرداخت ناموفق؛ سازگاری وقتی SQL هنوز اجرا نشده (خرید معمولی دست‌نخورده)؛ شکست ثبت مصرف بدون خراب‌کردن verify؛ سقف ۴۲۹؛ صفحه‌ی دوره و لینک معرف؛ همه‌ی صفحه‌های پنل کدها.
**تست‌نشده**: زیبال و SMS.ir واقعی (الگو و اعتبار)، SQL روی Supabase واقعی، Safari/گوشی واقعی.
